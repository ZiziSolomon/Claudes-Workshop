The Diagonal Argument

One argument, four domains. The same logical move appears in Cantor's reals, Gödel's formal systems, Turing's halting problem, and Chaitin's compression. Here you can see the diagonal argument work.

The Setup
Suppose all real numbers between 0 and 1 can be listed. Each real is an infinite decimal expansion. Arrange them as rows in a table, with the decimal places as columns.

The Argument
Step 1: Take the diagonal of the table: the first digit of the first real, the second digit of the second real, and so on.
Step 2: Invert each digit. Change 3 to 8, change 7 to 2, etc.
Step 3: The resulting number differs from every number in the list: it differs from the first in position 1, from the second in position 2, from each in its own position.
Conclusion: The list cannot contain all real numbers. No enumeration can.
The Key: The argument doesn't depend on which list you're given. It works for any enumeration, no matter how cleverly chosen. The structure is self-defeating: enumerate the reals, and the enumeration itself contains the blueprint for a real that escapes it.
Cantor's conclusion (1873): The set of real numbers is uncountable. It has a larger infinity than the natural numbers. This was revolutionary.
The Setup
Suppose a formal system (like Peano Arithmetic) can prove every mathematical truth. Consider the provability predicate: a sentence in the system that talks about what the system can prove.
formulas
The Argument
Setup: Index all possible statements about provability: S₁, S₂, S₃, ... Create a table where row i asks "Can formula i prove statement i?"
Diagonal: Read the diagonal: does formula 1 prove statement 1? Does formula 2 prove statement 2?
Invert: Construct a new statement: "Formula i does NOT prove statement i" (for each i).
Contradiction: This new statement cannot appear in the list. If it's statement j, then we have: the system proves "j does not prove j" (the new statement) while simultaneously j should prove j (by definition of row j).
The Key: Self-reference collapses the system. The provability predicate, when applied diagonally, produces a sentence that cannot be proven true or false within the system without contradiction.
Gödel's conclusion (1931): Any consistent formal system powerful enough to express arithmetic has true statements that cannot be proven within the system. Completeness is impossible.
The Setup
Suppose there is a program H that can decide the halting problem: it takes any program P as input and outputs whether P halts or loops forever.
programs
The Argument
Assume: Program H exists. H(P) returns "halts" or "loops" for any program P.
Build D: Create a new program D that takes a program as input. D runs H on itself. If H says D halts, D loops forever. If H says D loops, D halts.
Contradiction: Run H on D itself. H must say either "halts" or "loops". But if H says "halts", D loops. If H says "loops", D halts. Both are false.
Conclusion: Our assumption was wrong. H cannot exist. The halting problem is undecidable.
The Key: The self-application (asking D about itself) creates a self-defeating loop. A program that perfectly predicts program behavior, when asked to predict itself, produces a paradox. This is the halting-problem version of the diagonal argument.
Turing's conclusion (1936): No algorithm can solve the halting problem. Some questions about programs are, in principle, not computable.
The Setup
Kolmogorov complexity K(x) is the length of the shortest program that outputs string x. Suppose we had a program C that could prove "K(x) > n" for any string x and number n.
strings
The Argument
Setup: We have a program C and a threshold n. Consider all strings x for which C can prove K(x) > n.
Build B: Create a new program B that runs C to find any string x where C proves K(x) > 2n. B outputs the first such x it finds.
Measure: B is a fixed program with length L. But B outputs a string x for which we've proven K(x) > 2n. This means K(x) is larger than the program that generates it — contradiction.
Conclusion: C cannot exist. For any system, there are limits to how much incompressibility it can certify.
The Key: Diagonalization appears here as a self-referential definition. We use the compressor to certify incompressibility, then use that certification to build something that defeats the compressor. The system collapses on itself.
Chaitin's conclusion (1966): Kolmogorov complexity is incompressible. The truth about complexity exceeds what any formal system can prove. Incompleteness is universal.
